# Агенты исполнителей

В этой папке лежит по одному файлу на каждую строку таблицы исполнителей из
`executor-catalog/SKILL.md`: `impl-medium.md`, `review-hard.md`,
`doc-typist.md` и так далее. Каждый файл — это субагент Claude Code. Он
описывает, **как** запускается исполнитель: модель (`model:`), уровень
рассуждения (`effort:`), доступные инструменты (`tools:` — у ревьюеров и
`code-explorer` только чтение) и короткий системный промпт.

**Кто** и **когда** запускает исполнителя, решает `executor-catalog`, а саму
задачу исполнитель получает пакетом в промпте от навыка-диспетчера (`work`,
`plan`, `doc-review` и других). Вызывать этих агентов напрямую не нужно:
навыки вызывают их сами через `Agent` с `subagent_type: "<имя>"` и без
параметра `model`. Если навыки установлены плагином, имя агента получает
приставку плагина (`dev-pipeline:<имя>`); каталог это учитывает.

## Установка

Есть два способа. Выберите **один**: если поставить оба, каждый навык окажется
в двух копиях.

### Способ 1. Плагин Claude Code

Эта папка — плагин `dev-pipeline` (паспорт в `.claude-plugin/plugin.json`),
а маркетплейс описан в `.claude-plugin/marketplace.json` в корне репозитория.
В Claude Code:

```
/plugin marketplace add <путь к репозиторию или его git-адрес>
/plugin install dev-pipeline@dev-pipeline-marketplace
```

Обновления приходят при обновлении маркетплейса, когда в `plugin.json` поднята
версия. Агенты из плагина называются `dev-pipeline:<имя>`.

Плагин приносит с собой два MCP-сервера (`.mcp.json`): **Figma**
(`https://mcp.figma.com/mcp`) и **Context7** (`https://mcp.context7.com/mcp`).
Если у вас такие серверы уже подключены, работают ваши, а серверы плагина
не используются. Context7 работает сразу. Figma нужно один раз авторизовать:
в Claude Code выполните `/mcp`, выберите сервер Figma и войдите в аккаунт.
Без этого `ui-design` не сможет рисовать кадры, `screen-spec` — читать их, а `frontend` — сверять экран с
макетом. При установке через `install.sh` (способ 2) серверы не ставятся —
подключите их сами (`claude mcp add`).

### Способ 2. Симлинки

Запасной вариант — только если плагин поставить нельзя. Не ставьте оба способа
сразу: каждый скилл окажется в двух копиях (`work` и `dev-pipeline:work`), и
правки разъедутся. Скиллы набора вызывают друг друга и агентов по полному имени
`dev-pipeline:<имя>`; без плагина срабатывает запасное короткое имя.

Из корня этой папки навыков:

```bash
bash install.sh
```

Скрипт создаёт симлинки:

- каждый `_agents/*.md` (кроме этого README) → `~/.claude/agents/`;
- каждую папку навыка с `SKILL.md` → `~/.claude/skills/`, кроме черновиков
  из переменной `DRAFTS` в начале скрипта (сейчас черновиков нет).

Скрипт можно запускать повторно. Существующий файл или папку, которые не
являются симлинком, он не трогает — только предупреждает. Симлинк заменяет,
только если тот указывает в другое место. Если задана переменная
`CLAUDE_CONFIG_DIR`, ссылки создаются в ней вместо `~/.claude`.

После установки перезапустите Claude Code, чтобы он подхватил агентов и
навыки. Если навык сообщает, что агент не найден, — значит, установка не
выполнялась или сессия не перезапущена.

Удалить всё, что поставил скрипт (только симлинки, ведущие в эту папку):

```bash
bash install.sh --uninstall
```

## Как поменять модель или effort

Модель и effort исполнителя записаны **только** в его файле здесь, в
строках `model:` и `effort:`. Чтобы перевести уровень на другую модель,
поправьте одну строку в одном файле — ни каталог, ни планы, ни навыки
менять не нужно. Поскольку установлены симлинки, изменение сразу попадает в
`~/.claude/agents/`; перезапустите сессию.

Перед сменой прочитайте `executor-catalog/references/model-economics.md`:
там правила (без моделей OpenAI; ревьюер кода не на той же модели, что
исполнитель) и что было замерено. Если обоснование
перестало быть верным, поправьте его в том же изменении.

Новая строка каталога = новая строка в таблице `executor-catalog` плюс новый
файл здесь с тем же `name:`, плюс строка в `.claude-plugin/plugin.json` →
`agents` (плагин грузит только перечисленные там файлы), затем
`bash install.sh`. При смене модели поднимите `version` в `plugin.json`, чтобы
обновление дошло до тех, кто поставил плагин.
